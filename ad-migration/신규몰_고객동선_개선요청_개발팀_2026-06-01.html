📌 광고 이전 전 점검 요지
배경.com 파워링크 광고를 신규몰(.kr)로 이전 검토 중. 광고 클릭은 모바일 중심이나, PC 자연 유입도 함께 운영 중.
현 상태 점검모바일 첫 화면 전송량 약 30MB, PC는 약 32MB 수준(이미지 모바일 376개·PC 495개·HTML 압축 미적용). 양쪽 모두 로딩 지연 우려 있음.
보완 없이 이전 시모바일 광고 클릭 후 이탈 늘어날 수 있음 → 광고 효율 저하 가능성. PC 자연 유입도 동일 영향 가능.
보완 후 이전 시모바일·PC 양쪽이 가벼워져 광고비 대비 상품 조회·전화 문의 전환이 개선될 여지.
적용 범위모바일·PC 동시 적용. 핵심 3개 작업(압축·캐시·이미지 변환)은 사이트 전체에 자동 적용되어 한 번 작업으로 양쪽 동시 개선.
필요 비용외부 결제·신규 계약 없음 (자체 운영 서버). 개발팀 작업 시간만 발생.
진행 기간개발팀 일정 체크 필요 (작업량·우선순위 회신 후 확정)
진행 방식광고 이전을 게이트로 묶지 않음. 작업 진행과 동시에 .com 광고 1~2개 그룹부터 시범 이전 병행 → 2~4주 문의 추이 보고 확대 여부 결정.
유의 사항시안·도면 이미지는 원본 보존 처리. 디스크 사용량 일부 증가 (변환본 저장).
※ 본 박스는 사업 배경 안내용. 기술 세부사항은 아래 1~7번(개발팀 명세) 참조.

3. 작업 요청 (우선순위 순)

HTML 응답 압축 켜기 (gzip/brotli) 모바일·PC 자동 동시
현재 모바일 647KB·PC 912KB가 비압축으로 전송. mod_deflate 활성 시 양쪽 약 130~180KB로 줄어듦 (텍스트 80% 절감). Apache 사이트 전체 적용.
난이도 하 · 작업량 30분 · 효과 즉효 · .htaccess 한 파일
이미지 Cache-Control 헤더 추가 모바일·PC 자동 동시
현재 이미지에 max-age 없음. 재방문 시 매번 304 검증 발생. Cache-Control: public, max-age=31536000, immutable 추가 시 재방문 거의 0 요청. 사이트 전체 적용.
난이도 하 · 작업량 30분 · 효과 재방문 시 큼 · mod_expires
이미지 WebP/AVIF 자동 변환·서빙 모바일·PC 자동 동시
원본 JPG 유지하고, WebP·AVIF 사본을 같은 폴더에 함께 두기. mod_rewrite로 Accept 헤더 보고 자동 분기. 신규몰 이미지 샘플 10장 WebP 변환 시 평균 79% 절감 실측. 이미지 디렉토리 /gsfiles_room/를 모바일·PC가 공유하므로 한 번 변환으로 양쪽 적용.
난이도 중 · 작업량 1~2일 · 효과 전송량 모바일 30→6MB · PC 32→7MB · 디스크 약간 추가
lazy-load + picture 폴백 템플릿 구조 확인 필요
현재 모바일·PC 양쪽 0건 적용. 첫 화면 밖 이미지가 즉시 다 다운로드됨. native lazy + picture 태그 적용 시 첫 화면 1MB 미만으로 떨어짐. PC·모바일 PHP 템플릿이 공통이면 한 번에 끝, 분리돼 있으면 양쪽 둘 다 수정.
난이도 중 · 작업량 1일 (공통 시) / 1.5~2일 (분리 시) · 효과 초기 로딩 큼

4. 구현 가이드

4-1. 압축·캐시 헤더 (.htaccess 또는 Apache conf)
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json
</IfModule>

<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/jpeg "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType image/avif "access plus 1 year"
  ExpiresByType text/css "access plus 30 days"
  ExpiresByType application/javascript "access plus 30 days"
</IfModule>

Header set Cache-Control "public, immutable" env=is_static
4-2. picture 태그 (PHP 템플릿)
<!-- AVIF 우선 → WebP 폴백 → JPG 최종 폴백, lazy-load 적용 -->
<picture>
  <source srcset="/gsfiles_room/2023/11/{hash}.avif" type="image/avif">
  <source srcset="/gsfiles_room/2023/11/{hash}.webp" type="image/webp">
  <img src="/gsfiles_room/2023/11/{hash}.jpg"
       loading="lazy" decoding="async"
       width="1080" height="1480" alt="상품명">
</picture>
시안·도면 이미지는 변환 제외 (견적 의사결정에 영향). 별도 디렉토리 분리 권장: /gsfiles_room/drawing/ → 변환 스크립트 --exclude drawing.
4-3. 이미지 변환 방식 선택지
방식월 비용특징

8. 개발팀 확인 필요 항목

8-A. 템플릿 구조PHP 템플릿이 모바일·PC 공통 컴포넌트 기반인지, 별도 파일로 분리돼 있는지. 공통이면 ④⑥ 작업 한 번에 끝, 분리면 양쪽 수정.
8-B. PC 메인 정보량PC 메인 이미지 495개 중 첫 화면 유지·carousel 전환·삭제 기준. UX·SEO 영향 협의 (웹팀 합의 후 결정).
8-C. 외부 리소스 출처script·CSS가 PC·모바일 공통 헤더에서 로드되는지, 분리됐는지.
8-D. 이미지 디렉토리/gsfiles_room/ 쓰기 권한·백업 정책. 변환본 저장 가능 여부.
8-E. CDN 사용 여부외부 측정상 미사용으로 보임. 사실 확인 후 자체 변환(권장) 또는 CDN 변환 중 선택.
8-F. 시안·도면 분리변환 제외 대상(시안·도면·실측 이미지) 식별 기준. 별도 디렉토리 분리 가능 여부.

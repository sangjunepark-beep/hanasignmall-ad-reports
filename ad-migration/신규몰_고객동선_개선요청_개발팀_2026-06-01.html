신규몰(.kr) 모바일 페이지 최적화 요청

개발팀 전달용 · 모바일 광고 유입 페이지 무게·로딩 속도 개선 · 2026-06-01 (v5: 이미지 자동화 인프라 결정 중심)
배경 — .com 파워링크 광고를 신규몰(.kr)로 이전 검토 중. 광고 클릭은 모바일 중심이고, 사인물 업종 특성상 매출의 90%가 전화·카톡 상담 주문(CS). 광고 이전 전에 .kr 모바일 페이지 로딩 속도가 광고 랜딩으로서 무리가 없는지 점검한 결과와 개선 방향입니다. 본 문서는 모바일 UA(iPhone Safari)로 직접 측정한 결과 기반입니다.
이 문서가 의도하지 않는 것 — "지금 .kr이 부족하다"는 책임 추궁이 아닙니다. 광고 이전 전 모바일 페이지 무게를 함께 다듬자는 협업 요청입니다. 우선순위·일정·구현 방식은 개발팀 의견에 따라 조정합니다.

문제점 + 개선 방향

심각 상1. 모바일 페이지 무게 — 광고 이탈 가능성
현상m.hanasignmall.kr 메인 HTML 647KB, 이미지 태그 376개. 상품 상세에 비최적화 long-image 다수.
구몰 비교m.hanasignmall.com 메인 130KB / 이미지 78개.
영향광고 클릭당 과금 환경에서 첫 화면 진입 전 이탈 가능. 유력 가설 중 하나(LCP·이탈률 실측은 GA/RUM 별도 확인 필요).
개선 방향 — 핵심: 이미지 변환 자동화
① 이미지 포맷 자동 변환 (운영자 부담 0) — 원본 JPG는 그대로 두고, 더 가벼운 포맷(AVIF / WebP)으로 자동 변환·서빙. 운영자는 평소처럼 JPG 업로드, 변환·서빙은 인프라가 처리.
[서버 저장] [브라우저 요청] [응답] hanasm.jpg (800KB) ──── iPhone Safari (AVIF 지원) ──→ hanasm.avif (160KB) hanasm.webp (240KB) ──── Android Chrome (AVIF 지원) ──→ hanasm.avif (160KB) hanasm.avif (160KB) ──── 구형 브라우저 (둘 다 미지원) ──→ hanasm.jpg (800KB)
포맷별 크기JPG 100% (기준) · WebP ~70% · AVIF ~50%. 화질 손실은 사람 눈으로 거의 인식 불가(설정 기준).
고객 체감같은 이미지를 더 빨리 받음. 페이지 로딩·LCP 단축.
사인물 특수시안·도면·실측 이미지는 변환 제외(견적 의사결정 영향). 상품 마스터에 유형 플래그 권장(catalog / proof / drawing).
변환 방식 비교 (운영자 부담 없는 자동화가 핵심)
D. Cloudflare Polish (1순위 검토)현재 Cloudflare Pro 플랜 사용 중이면 토글만으로 자동 WebP/AVIF 변환·캐시. 코드 변경 0줄. 현재 Cloudflare 사용 여부부터 확인.
A. 변환 CDNCloudflare Images / imgix / 자체 imgproxy. 이미지 URL에 ?w=1080&fmt=webp 파라미터로 자동 변환·캐싱. 원본 보존. Cloudflare Images 가격: 저장 $5/10만장 + 전송 $1/10만장 + 변환 $0.5/1,000건. imgproxy는 SW 라이선스만 무료(서버·트래픽 별도).
B. 서버 변환nginx image_filter 또는 sharp/imagemagick으로 첫 요청 시 변환→캐시. 주의: nginx image_filter WebP는 libgd가 WebP 지원으로 빌드돼야 함. sharp는 동시 워커 제한·메모리 모니터링 필수.
C. 일괄 변환 스크립트서버 이미지 디렉토리 스캔 → sharp/imagemagick으로 AVIF·WebP 변환해 원본 옆에 저장(.jpg + .webp + .avif) → nginx rewrite로 Accept 헤더 기반 응답. 함정: 디스크 2~3배 + 신규 업로드 hook 없으면 6개월 뒤 재발. Vary: Accept 헤더 필수.
권장 결정 순서① D 가능 여부 확인 → ② 불가 시 C(기존 자산 정리) + A 또는 B(신규 업로드 자동 변환). 셋 중 하나 골라 운영자 부담 0 + 신규 업로드 자동화 둘 다 만족.
② lazy-load + picture 폴백 — 첫 화면 밖 이미지는 native lazy + 비율 고정으로 CLS 방지:
<!-- AVIF 우선, WebP 폴백, JPG 최종 폴백 -->
<picture>
  <source srcset="/data/goods/47202_detail_01.avif" type="image/avif">
  <source srcset="/data/goods/47202_detail_01.webp" type="image/webp">
  <img src="/data/goods/47202_detail_01.jpg"
       loading="lazy" decoding="async"
       width="1080" height="1480" alt="홀로그램 주차스티커 상세">
</picture>
③ 메인 이미지 수 축소 — 376개 → 첫 화면 노출분만 즉시 로딩, carousel/탭 콘텐츠는 클릭 시 로딩.
④ 정적 리소스 캐시·압축 — Cache-Control: max-age 30d, gzip/brotli, HTTP/2.
⑤ 광고 랜딩 경량 모드 (선택) — utm 파라미터 감지 시 핵심 정보(대표이미지·가격·옵션)만 우선 렌더.
목표 — 광고 랜딩 페이지 모바일 LCP ≤ 2.5초, 상세 총 전송량 직전 대비 −30%, 시안·도면 원본 보존.

개선 방향
① 모바일 조건부 로딩 — PC 전용 위젯/슬라이더/대형 배너는 모바일에서 로드 자체 스킵(display:none만으론 다운로드 발생).

목표 — 모바일 초기 로딩 JS/CSS 30% 이상 감축. 1번과 연동.

착수 전 개발팀 회신 요청

① Cloudflare 사용 여부 (D안 가능성 우선 확인) — Cloudflare(Pro 이상) 사용 중이면 Polish 토글만으로 자동 WebP/AVIF. 미사용 시 A/B/C 중 가능 옵션. 현재 이미지 서빙 경로·CDN·캐시 헤더 정책
② utm 파라미터 명세 — 광고 링크 utm_source/medium/campaign 키 규칙 + GA/GTM 수집 여부 + JS 리다이렉트(m.도메인 분기) 시 utm 보존 여부 (시범 이전 효과 측정용)
③ 프레임워크 + 상품 마스터 구조 — 신규몰 프론트 프레임워크 + 상품 마스터에 "상세 이미지 유형 플래그"(catalog / proof / drawing) 추가 가능 여부 + 기존 이미지 디렉토리 권한·백업. drawing은 /data/goods/drawing/ 별도 경로 + 변환 스크립트 --exclude drawing로 분리 권장

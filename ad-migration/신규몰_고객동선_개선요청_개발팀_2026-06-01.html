심각 상1. 모바일 페이지 무게 — 광고 이탈 가능성
현상모바일 도메인(m.hanasignmall.kr) 메인 HTML 647KB, 메인 이미지 태그 376개. 상품 상세에 비최적화 long-image 다수 존재.
구몰 비교m.hanasignmall.com 메인 130KB / 이미지 78개. 모바일 전용 페이지로 경량.
영향광고 클릭당 과금 환경에서 첫 화면 진입 전 이탈 가능. 유력 가설 중 하나(LCP·이탈률 실측은 GA/RUM 데이터 별도 확인 필요).
개선 방향
① 상세 이미지 표준화 (상품유형 분기) — 일반 상품 상세 long-image는 AVIF 우선, WebP 폴백·max 1080px·200KB/장 목표. 시안·도면·실측 이미지가 견적 의사결정에 직접 영향인 상품은 원본 보존(상품 마스터에 유형 플래그 권장).
① 변환 방식 비교 (운영자 부담 없는 자동화가 핵심)
A. 변환 CDNCloudflare Images / imgix / 자체 imgproxy. 이미지 URL에 ?w=1080&fmt=webp 파라미터로 자동 변환·캐싱. 원본 보존. Cloudflare Images 가격: 저장 $5/10만장 + 전송 $1/10만장 + 변환 $0.5/1,000건(자사 이미지 수량 기반 실비 산정 필요). imgproxy는 SW 라이선스만 무료(서버·트래픽 비용 별도).
B. 서버 변환nginx image_filter 모듈 또는 백엔드 sharp/imagemagick으로 첫 요청 시 변환→캐시. 주의: nginx image_filter WebP는 libgd가 WebP 지원으로 빌드돼야 함(배포판 기본 nginx 미지원 多). sharp 사용 시 동시 워커 제한·메모리 모니터링 필수.
D. Cloudflare Polish (이미 Pro면 0줄)Cloudflare Pro 플랜 사용 중이면 토글만으로 자동 WebP/AVIF 변환·캐시(추가 비용 없음). 코드 변경 0줄. 다른 옵션 검토 전 현재 Cloudflare 사용 여부부터 확인 권장.
C. 일괄 변환 스크립트서버 이미지 디렉토리 스캔 → sharp/imagemagick으로 AVIF·WebP 변환해 원본 옆에 저장(47202_detail.jpg + .webp + .avif) → nginx rewrite로 Accept 헤더 기반 응답. 함정: 디스크 사용량 2~3배 + 신규 업로드 hook(관리자 등록 직후 변환 트리거) 없으면 6개월 뒤 재발. Vary: Accept 헤더 필수(CDN 캐시 오염 방지).
권장D 가능 여부 확인 → 불가 시 C(기존 자산 정리) + A 또는 B(신규 업로드 자동 변환). 운영자(상품등록 담당)는 평소처럼 JPG 업로드만 — 변환·서빙은 인프라가 처리.
② lazy-load + AVIF/WebP 폴백 — 첫 화면 밖 이미지는 native lazy + 비율 고정으로 CLS 방지. picture 태그로 포맷 폴백:
<!-- AVIF 우선, WebP 폴백, JPG 최종 폴백 -->
<picture>
  <source srcset="/data/goods/47202_detail_01.avif" type="image/avif">
  <source srcset="/data/goods/47202_detail_01.webp" type="image/webp">
  <img src="/data/goods/47202_detail_01.jpg"
       loading="lazy" decoding="async"
       width="1080" height="1480" alt="홀로그램 주차스티커 상세">
</picture>
③ 메인 이미지 수 축소 — 376개 → 첫 화면 노출분만 즉시 로딩, carousel/탭 콘텐츠는 클릭 시 로딩.
④ 정적 리소스 캐시·압축 — 이미지 CDN 또는 Cache-Control: max-age 30d, gzip/brotli, HTTP/2.
⑤ 광고 랜딩 경량 모드 (선택) — utm 파라미터 감지 시 핵심 정보(대표이미지·가격·옵션)만 우선 렌더.
목표 — 광고 랜딩 페이지 모바일 LCP ≤ 2.5초, 상세 총 전송량 직전 대비 −30%, 시안·도면 원본 보존.
